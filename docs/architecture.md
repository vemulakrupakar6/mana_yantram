# Architecture

Mana Yantram is a modular monolith with independent React and Express processes. The two applications share a workspace and lockfile. The frontend talks only to versioned REST endpoints. The Express app is initialized separately from its HTTP listener so Supertest can exercise the same routes and middleware.

| Area            | Design                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Frontend        | React Router layouts and role guards, React Hook Form and Zod, TanStack Query for account and portal API state, Zustand for in-memory session data, English and Telugu resources via i18next                                                                                                                                                                                                    |
| Backend         | Express modules (routes, schema, service and tests per module) for health, authentication, users, department user administration, masters, files, farmers and assisted registration, providers, equipment, availability, operators and provider verification, Prisma's PostgreSQL driver adapter, structured Pino logs, server-owned request IDs and consistent response envelopes              |
| PostgreSQL      | Prisma migrations (plus raw SQL for CHECK constraints and `NULLS NOT DISTINCT` indexes that Prisma cannot model), separate role membership and per-role onboarding, explicit consent with purposes, jurisdictions, geography and service masters, and audit records for every state change                                                                                                      |
| Authorization   | JWT claims identify the user and session family. The API reads current user status, membership, permissions and session state before serving protected routes. Roles map to permissions through an explicit matrix that the seed keeps in sync. Officers carry a jurisdiction (state, district or mandal); every officer query is filtered through it and an out-of-scope resource answers 404. |
| Refresh         | Random opaque cookie values, SHA-256 hashes in PostgreSQL, absolute expiry inherited at each rotation. Account row locks serialize login, refresh, logout and password changes. Reuse of a rotated, unexpired token revokes the family.                                                                                                                                                         |
| Browser session | Axios coordinates one refresh at a time per tab and retries expired-token requests once. Web Locks serialize cookie writes across tabs where available. The browser may ask the user to sign in again if simultaneous refreshes occur without Web Locks.                                                                                                                                        |
| Revocation      | Logout revokes the current family. Logout-all and password change revoke all families for the account. Protected requests reject revoked families even if their JWT remains within its validity period.                                                                                                                                                                                         |
| Abuse controls  | PostgreSQL fixed-window counters for sensitive endpoints. Login is limited per IP and per normalized username/IP pair. A periodic job removes expired entries.                                                                                                                                                                                                                                  |
| Browser trust   | Exact CORS allowlist, HttpOnly same-site refresh cookie, explicit origin and custom header checks for cookie operations, Secure cookies in production mode and SameSite=None requires Secure.                                                                                                                                                                                                   |

## Milestone 3 design notes

| Area                    | Design                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| File storage            | Files live on server disk under `STORAGE_ROOT` as `private/<bucket>/<year>/<month>/<uuid>.<ext>`; the database keeps only references. The type is detected from the bytes. Uploads are attached in a second step; unattached ones are deleted after 24 hours. Replaced files are soft-deleted and kept for audit. Downloads go through a policy check (owner, the provider's owner, or an officer in jurisdiction, which is audited) and are streamed with `nosniff` and `no-store`. The browser downloads through Axios and uses object URLs. |
| Sensitive fields        | Aadhaar: only the last four digits and an HMAC-SHA256 keyed hash are stored. Bank account numbers: AES-256-GCM with `FIELD_ENCRYPTION_KEY`, masked in every response, revealed only through an audited officer endpoint.                                                                                                                                                                                                                                                                                                                       |
| Provider status machine | `DRAFT, SUBMITTED, RETURNED, APPROVED, REJECTED, SUSPENDED, BLACKLISTED`. Every transition locks the provider row, checks the from-status, writes a verification-history row and an audit row. A single `assertProviderEditable` helper decides which sections can change in which status.                                                                                                                                                                                                                                                     |
| Concurrency             | Provider edits and transitions take a row lock (`SELECT ... FOR UPDATE`); availability blocks take a per-unit advisory lock so overlapping requests cannot both succeed. Interactive transactions use one connection, so reads inside them are flat, sequential queries (relation counts and joins are done after commit).                                                                                                                                                                                                                     |
| Money, area, time       | Integer paise, `Decimal(10,2)` acres, latitude and longitude as `Decimal(9,6)`, working hours as minutes from midnight, `timestamptz` timestamps.                                                                                                                                                                                                                                                                                                                                                                                              |
| Accounts                | Everyone signs in with a username and password. Accounts created by someone else carry a temporary password and `mustChangePassword`, which the API enforces on every endpoint until it is changed. There is no self-service recovery; an administrator, provider or field agent resets it.                                                                                                                                                                                                                                                    |
| Testing                 | Vitest and Supertest integration tests per module, Vitest component tests, and Playwright end-to-end scenarios (farmer onboarding, the provider application, the return and approval flow, deactivation) plus an automated overflow check at 360, 768 and 1440 px.                                                                                                                                                                                                                                                                             |

The only browser preference kept in local storage is the selected language. Opacity and cryptographic hashing keep refresh values out of the database and audit records. Desktop and mobile screens use the same components and locally stored agricultural photography.

Milestones 1 and 2 are for local development and restricted demonstrations. Demo policy version `demo-1.0` is the version recorded at signup. Milestone 3 adds the farmer and provider profiles, geographic and service masters, file storage, equipment and rate cards, operators, availability, and provider verification. Search, booking, payments, grievances, reports and notification delivery belong to later milestones.
